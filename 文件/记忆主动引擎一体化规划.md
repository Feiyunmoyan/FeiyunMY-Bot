# 记忆 + 主动引擎一体化规划

> 整理于 2026-06-11 讨论内容

---

## 一、当前系统的三层问题

### 1️⃣ 主动引擎的四断点

```
引擎想推 → 检索记忆 → 推给AI → AI生成回复 → 用户看到 → 用户回复
                                                      ↓
                                              回应率只有15%
```

| # | 断点 | 根因 | 本质 |
|:-:|:-----|:-----|:------|
| ① | **情境判断脱节** | `_judge_situation()` 只读 `last_chat_time` + 情感正负，没利用V3记忆的丰富元数据 | **主动引擎不会用记忆库** |
| ② | **推给AI ≠ AI真说了** | `_push_to_ai_chat()` 只是把提示词推SSE展示，没调LLM生成，AI没参与 | **引擎推的只是"画外音"** |
| ③ | **冷却函数恶性循环** | 久没聊→缩短冷却→频推送→用户不理→回应率更低→阈值更高 | **反馈回路太浅** |
| ④ | **AI口头确认陷阱** | AI在reasoning中想行动，但说完"我查查"就停了，没真调工具 | **意愿→行动缺通路** |

### 2️⃣ 记忆系统的五层问题链（串行耦合）

```
情感分析偏了 → 重要性虚高 → 阈值拦不住 → 不该存的存了 → 检索时一堆噪声
```

| 层级 | 问题 | 影响 |
|:----:|:-----|:------|
| ① 情感 | GoEmotions词典法对负面更敏感，情感强度虚高 | 重要性跟着涨 |
| ② 重要性 | `semantic_score` 权重 0.4 偏高，时效性降权依赖类型识别 | 信息密集的废话也高分 |
| ③ 类型识别 | 日志大量"未知"类型 | 时效性降权失效 |
| ④ 去重 | 短文本阈值 0.95 太严 | "嗯""好的"反复存 |
| ⑤ 遗忘 | 串行耦合，一层偏了全偏 | 该清的清不掉，该留的留不住 |

### 3️⃣ 记忆系统缺失的四个维度

| # | 缺失维度 | 现状 | 期望 |
|:-:|:---------|:-----|:------|
| ① | **记忆间关联网络** | 每条记忆独立存储，"用户喜欢猫"和"养了布偶叫团子"没关系 | 网状关联，一条话题链 |
| ② | **时间上下文** | 只分"创建/更新时间"，不区永久/临时/周期/过时 | 分层遗忘策略 |
| ③ | **用户反馈回写** | 反馈回路只调矩阵权重，没写回记忆 | 接住率/态度趋势回写到记忆 |
| ④ | **AI自身行为记录** | 只记用户行为 | 记AI的意图和行动状态 |

## 二、问题之间的依赖关系

```
                        ┌─────────────────┐
                        │ 主动引擎推不好  │ ← 回应率15%
                        └────────┬────────┘
                                 │ 因为
                                 ▼
              ┌──────────────────────────────┐
              │ 情境判断只读到噪声记忆       │
              │ "日常维系"×6 → 单调乏味     │
              └────────┬─────────────────────┘
                       │ 因为
                       ▼
   ┌────────────────────────────────────────────┐
   │ 记忆库里"嗯""好的"堆太多                  │
   │ 检索出来一堆没营养的内容                  │
   └────────┬───────────────────────────────────┘
            │ 因为
            ▼
   ┌────────────────────────────────────────────┐
   │ ① 情感偏负面 → 重要性虚高 → 阈值拦不住   │
   │ ② 类型识别不准 → 时效性降权失效          │
   │ ③ 去重太严 → 短文本反复存               │
   │ ④ 无关联维度和用户反馈 → 谁重要分不清   │
   └────────────────────────────────────────────┘
```

**核心矛盾**：最底层的问题（情感偏、类型不准、去重太严、缺维度）→ 记忆质量差 → 主动引擎检索到的内容没营养 → 推送没人理 → 恶性循环

## 三、规划方向：三阶段

### Phase 1 🟢 打通现有通道（改动最小）

**目标**：让主动引擎会用记忆系统已有的数据

| 改什么 | 怎么改 |
|:-------|:-------|
| `_judge_situation()` | 用上 VAD坐标 + 记忆类型 + 重要性，不再只看 `last_chat_time` |
| 检索策略 | 记忆通道优先 `memory.query()` 语义检索，`get_recent()` 只兜底 |
| 情境矩阵 | 现在5种情境只有"日常维系"被触发，调权重让其他情境也能触发 |

**效果**：不再万年日常维系，能触发情感关怀、久别重逢

### Phase 2 🟡 记忆系统质量提升

**目标**：修记忆系统本身的5层问题，同时补充缺失维度

| 改什么 | 怎么改 |
|:-------|:-------|
| 情感词典 | 平衡正面/负面敏感度，降低日常对话的情感虚高 |
| 类型识别 | 减少"未知"比例，让时效性降权生效 |
| 去重阈值 | 短文本降低阈值（0.95→0.85），减少重复存储 |
| 新增维度① | **记忆间关联**：同话题的记忆加 `topic_id` 或 `thread_id` 字段 |
| 新增维度② | **时间分层**：永久/临时/周期/过时 四类标签 |
| 新增维度③ | **用户反馈回写**：接住率、态度趋势回写到记忆元数据 |
| 新增维度④ | **AI行为记录**：AI的意图和行动状态存入记忆 |

**效果**：记忆质量提升，检索出来的内容有营养

### Phase 3 🔴 记忆+主动引擎闭环

**目标**：让AI能看到自己的历史意图，形成真正的主动性

| 改什么 | 怎么改 |
|:-------|:-------|
| AI意图记录 | AI在reasoning中表达"想查XX" → 系统自动存一条待办记忆 |
| 主动引擎读取 | 读到"AI上次想查没查" → 推送给AI续上 |
| 反馈循环 | 用户接住/没接住 → 影响话题权重 → 下次更好 |

**效果**：不再是"引擎推话头等用户接"，而是"AI主动发起对话"
