## 2. 评测集：让"玄学"变成"实验"

### 2.1 它是什么

**一份带答案的题。**

- 一批输入（查询、用户说的话）
- 每条的**标准答案**（什么才算正确结果）
- 一个**指标**，把"对不对"变成一个数字

关键不是"有答案"，而是**"被测系统没见过这个答案"**——这就是课程里反复讲的**数据泄漏 / 过拟合测试集**。

### 2.2 检索系统的评测集长什么样

memoria 不做梯度下降，它做的是"这句话来了，该捞出哪几条记忆"。所以它的题面是「查询 → 应该召回哪些记忆」：

| 查询（用户说） | 标准答案（应该被召回的记忆） |
|---|---|
| "上次说的那个课题怎么样了" | ① 被布置 YOLO 视觉课题 ② 提到需要 GPU 集群 |
| "我最近很累" | ③ 连续半年做项目、想休息几个月 |
| "那个记忆公式你还记得吗" | ④ 三层球形场 + 量子迁跃设计 |
| "晚安" | ⑤ （可能什么都不该召回，测"空召回"是否正确） |

### 2.3 指标怎么算

假设标准答案是 2 条，系统返回了前 5 条（`retrieval_top_k: 5`）：

- **recall@5** = 命中的标准答案数 / 标准答案总数 → 命中 1 条就是 `1/2 = 0.5`
- **precision@5** = 前 5 条里真正有用的比例
- **MRR** = 正确那条排在第几位的倒数（排第 1 → 1.0，排第 3 → 0.33）

> 核心问题：**5 到底是不是 3 更好、10 是不是更好？** 没有这组标注，这个问题永远答不了。

### 2.4 怎么造（一个下午，200 条）

1. 从聊天日志里随便挑 50 段真实对话（不要挑"漂亮的"）
2. 每段写一句"用户可能怎么问"
3. 每句下面写"这时候应该想起哪 1~3 条记忆"
4. 存成 jsonl 文件，结束

**覆盖面比数量重要**，至少这五类各占一部分：

- 偏好类（"我喜欢什么"）
- 事实类（"我说过的那件事"）
- 情感类（"我现在情绪不好"）
- 时间类（"上周那个"）
- **久别重逢类**（"好久没聊了"）← 专门测艾宾浩斯衰减有没有删掉该留的

### 2.5 三个最容易踩的坑

1. **拿评测集当调参集**：调一次参数看一次成绩、调 50 次——这 200 条就被"背"下来了，成绩虚高。
   → **留 50 条永远不看，留到最后一测。**
2. **样本太干净**：全挑顺利的对话，测出来 0.95，线上照样崩。
   → 故意放一些模糊的、歧义的、答不出来的。
3. **标注自己前后矛盾**：同一种情况两次标得不一样。
   → **先写 10 条标注规范再开始标。**

### 2.6 jsonl 模板

```json
{"id": "q001", "query": "上次说的那个课题怎么样了", "gold": ["mem_20261019_yolo", "mem_20261019_gpu"], "note": "时间指代 + 跨域关联"}
{"id": "q002", "query": "我最近很累", "gold": ["mem_20260617_burnout"], "note": "情感类，应召回状态而非任务"}
{"id": "q003", "query": "晚安", "gold": [], "note": "空召回，不该硬捞记忆"}
```

### 2.7 标注规范示例（先定 10 条，再动手）

1. 一条记忆只记一件事，复合内容要拆开标注
2. "应该召回"的判定标准是：**不知道这条，回答就会出错或变冷**
3. 时间指代（"上次""前几天"）优先按最近的相关记忆标
4. 闲聊寒暄默认不召回，除非涉及情绪
5. 同义表述算命中（"课题""项目""那个视觉任务"视为同一查询意图）
6. 一条查询最多标 3 条 gold，多了说明标注粒度太粗
7. 不确定的样本标 `"note": "ambiguous"`，单独统计，不要硬猜
8. 情绪类查询：优标"情绪状态"记忆，而不是"事实"记忆
9. 久别重逢类：必须包含最近一次的重要记忆 + 至少一条长期偏好
10. 标完 20 条后再回看前 10 条，检查自己标准有没有漂移

## 3. 两层评测，别混在一起

| 层次 | 能否自动算 | 例子 | 怎么做 |
|---|---|---|---|
| **客观层** | ✅ | 记忆召回率、情绪分类 F1、响应延迟、上下文压缩保真度 | 脚本跑，进 CI |
| **主观层** | ❌ 必须人评 | "这句话该不该现在推给我""像不像她" | 攒 100 条真实推送，人工标「爽 / 无感 / 烦」，统计比例 |

`ActiveScheduler` 的**扰动指数、动态冷却、话痨模式**都属于第二层。**"打扰度"没有公式**——它的本质是采集人类偏好，和现在训练大模型用的 RLHF 是同一个思路。有推送历史表和反馈回路，缺的只是"把它变成指标"这一步。

## 4. 记忆归零问题（待决策）

### 现象

关机两个月再启动，记忆几乎被清空：

```python
# main.py —— 启动时执行一次艾宾浩斯记忆清理（即使服务器关机多天，开机时自动清理过期记忆）
memoria.cleanup_expired()
```

不是"慢慢忘"，是**开机瞬间一次性判定全部过期**。

### 为什么是三个月

由这三个参数决定，改一个就变：

```yaml
ebbinghaus:
  decay_factor: 0.1
  default_retention: 0.8
  cleanup_threshold: 0.3
```

**这是自己选的参数，不是命运。**

### 三个可选方案

- **A. 按"累计接触次数"折算保留度**，而不是按日历天数。聊过一百次的记忆，不该因为关机两个月就等于从没存在过。
- **B. 清理前先触发一次"久别重逢"情境**，给记忆一次唤醒机会（`SITUATION_MATRICES` 里本来就有这一项）。改动量：几十行。
- **C. 核层豁免**——V4 文档已设计：内层「核」（6 大基本情绪指向）不参与衰减，外层漂移但受核牵引。**漂走的是碎片，留下的是方向。**

### 一个提醒

时间轴是**单侧**的：它会忘，主人不会。所以"从熟悉变陌生"是一次性损失，不是对称的对等消失。
