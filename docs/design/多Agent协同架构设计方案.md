## 一、整体架构总览

```
                    🧑 用户
                    │  ↕ 不需要@，直接发消息
                    │
              ┌─────┴─────┐
              │  🧠 主脑   │ ← 项目经理
              │  + 🔔 主动引擎 │ ← 定时/记忆/监控触发
              └─────┬─────┘
                    │ @主脑（子Agent汇报用）
                    │
      ┌─────────────┼─────────────┐
      │             │             │
      │ @code       │ @design     │ @test
      ▼             ▼             ▼
  ┌────────┐  ┌────────┐  ┌────────┐
  │ 💻 Code  │  │ 🎨 Des │  │ 🧪 Test │
  │ Agent   │  │ Agent  │  │ Agent  │
  ├────────┤  ├────────┤  ├────────┤
  │ 人格设定 │  │ 人格设定 │  │ 人格设定 │
  │ 长期记忆 │  │ 长期记忆 │  │ 长期记忆 │
  │ 知识库📚 │  │ 知识库📚 │  │ 知识库📚 │

              ┌─────┴─────┐
```

## 二、核心交互规则

| 场景 | 交互方式 | 说明 |
|:----|:--------|:-----|
| 🧑 用户聊天 | 直接发消息 | 自动路由到主脑，不需要 `@` |
| 🧑 找特定 Agent | `@code 帮我写登录页` | `@` + 名字直接路由到对应 Agent |
| 🤖 Agent 汇报 | `@主脑 任务完成` | Agent 干完了，切回主脑审核 |
| 🤖 Agent 间协作 | `@design 我需要你设计这个组件` | 多边形网状结构，任意节点互通 |
| 🧑 中途介入 Agent | `@code 颜色改一下` | 直接在 code_agent 会话里回复 |
| 🔔 主动推送 | SSE 长连接 | 主动引擎推送给用户 |

### 2.1 多边形网状结构

不仅仅是主脑和用户可以联系，**多个点可以互相连接**：

```
    用户 ── 主脑 ── code_agent
      │              │
      ├── design_agent
      │              │
      └── test_agent ┘
```

任何一个节点都能通过 `@名字` 和另一个节点对话。

## 三、组件详细设计

### 3.1 🧠 主脑（项目经理）

**职责**：
- 和用户在同一会话，用户直接发消息就是和主脑交流
- 拆解任务、筛选合适的 Agent、创建工作空间
- `@agent` 派发任务，监督进度，汇总汇报
- 负责审核子 Agent 的成果

**双重身份**：
| 模式 | 触发方式 | 行为 |
|:----|:--------|:-----|
| 被动模式 | 用户发消息（无@） | 正常对话、拆解任务、回答问题 |
| 主动模式 | 主动引擎触发 | 定时提醒、记忆跟进、Agent完成通知 |

### 3.2 🤖 Agent 池

**每个 Agent 拥有**：
- **独立人格设定** — 不同角色有不同说话方式（如 code_agent 严谨、design_agent 创意）
- **独立长期记忆** — 专属 ChromaDB 集合，积累领域经验
- **独立知识库** — 可挂载专属知识库（如 code_agent 挂技术文档）
- **独立会话** — 每个 Agent 有自己的对话上下文，不互相干扰
- **可配置模型** — 每个 Agent 可选择不同的 LLM 模型

**Agent 之间的通信**：
- 通过 `@agent名` 在各自会话中路由
- Agent A `@agent B` → 系统拦截 → 路由到 B 的会话 → B 回复 → 结果返回 A

### 3.3 🔀 API 分发器（对话路由器）

**定位**：不是"并发节流阀"，而是 **"按顺序调度的对话路由器"**

```
消息来了（用户发的 / Agent发的 / 主脑发的）
      │
      ▼
┌───────────────────────────────┐
│  🔀 对话路由器                  │
│                               │
│  ① 解析 @ 前缀                 │
│     - 无 @ → 路由到主脑         │
│     - @主脑 → 路由到主脑        │
│     - @code → 路由到 code_agent │
│     - @design → 路由到 design   │
│                               │
│  ② 查找目标 Agent 的会话       │
│     - 不存在则自动创建          │
│     - 存在则追加到历史          │
│                               │
│  ③ 加载目标 Agent 的配置       │
│     - 使用的模型（从已有模型池选）│
│     - 人格设定（从已有预设选）   │
│     - 长期记忆注入              │
│     - 知识库挂载（从已有知识库选）│
└──────────────┬────────────────┘
               │
               ▼
┌───────────────────────────────┐
│  📤 按顺序调度                  │
│                               │
│  - 同一时间只处理一个请求       │
│  - 其他请求排队等待             │
│  - 用户请求 > 主脑 > Agent     │
│    （优先级排序）               │
│                               │
│  - 请求状态持久化到磁盘         │
│  - 重启后恢复排队状态           │
└──────────────┬────────────────┘
               │
               ▼
          LLM API
```

**关键设计**：
- **按顺序对话**，而不是一堆 Agent 同时说话
- 每个 Agent 的调用排队，一次一个
- 优先级：用户请求 > 主脑主动消息 > Agent 间消息

### 3.4 📋 工作空间（持久化+可视化）

**数据模型**：

```python
workspace = {
    "workspace_id": "uuid",
    "name": "博客项目",
    "status": "active",         # active / paused / completed / failed
    "created_at": "timestamp",
    "updated_at": "timestamp",
    
    # 项目全局信息
    "shared_context": {
        "project_description": "做个博客网站",
        "tech_stack": "Vue + FastAPI",
        "global_notes": "..."
    },
    
    # Agent 列表及状态（引用系统里已有的 Agent 配置）
    "agents": [
        {
            "agent_ref_id": "code_001",    # 引用系统里已注册的 Agent 配置
            "name": "code",
            "status": "done",
            "progress": "100%",
            "result_summary": "..."
        }
    ],
    
    # 任务列表（有向无环图 DAG）
    "tasks": [
        {
            "task_id": "t001",
            "agent": "code",
            "description": "用Vue搭建前端框架",
            "status": "done",
            "result": "...",
            "depends_on": []           # 依赖的任务ID
        }
    ],
    
    # Agent 的独立对话记录（工作空间级别，删除即消失）
    "agent_sessions": {
        "code": [...],
        "design": [...]
    }
}
```

**持久化策略**：

| 层级 | 存储方式 | 说明 |
|:----|:--------|:-----|
| 🟢 内存 | workspace 对象 | 运行时快速读写 |
| 🟡 磁盘 | `data/workspaces/ws_xxx.json` | 每次状态变化原子写入 |
| 🔵 SQLite | `data/feiyun.db` | Agent 对话历史持久化 |
| 🟠 备份 | `data/workspaces/backup/` | 定期备份 |

**原子写入保证**：
```python
def _save_to_disk(self):
    tmp_path = path + ".tmp"
    with open(tmp_path, "w") as f:
        json.dump(self.state, f)
    os.replace(tmp_path, path)  # 原子替换，防止断电写坏
```

**重启恢复流程**：

```
服务器启动
    │
    ├─ 扫描 data/workspaces/*.json
    │
    ├─ 对每个工作空间：
    │   ├─ completed → 归档
    │   ├─ active → 检查所有任务
    │   │   ├─ 全部 done → 标记 completed
    │   │   └─ 有 pending/working → 标记 paused
    │   │       └─ 主脑主动通知用户
    │   │          "主人，之前断电了，xx做到一半要继续吗？"
    │
    └─ 恢复 API 分发器的排队状态
```

## 四、🔔 主动型引擎

### 4.1 定位

主动引擎是**主脑的一个增强模块**，不是独立组件。

### 4.2 三引擎驱动

```
                    🔔 主动引擎（常驻后台）
                           │
        ┌──────────────────┼──────────────────┐
        │                  │                  │
        ▼                  ▼                  ▼
   ⏰ 定时引擎        🧠 记忆引擎        📊 监控引擎
   ──────────        ──────────        ──────────
   主人设的提醒        ChromaDB查询      系统资源监控
   定时任务           待跟进话题         Agent进度
                      "未完结"标记       磁盘/内存/CPU
```

### 4.3 主动消息优先级

| 优先级 | 类型 | 行为 |
|:-----:|:----|:-----|
| 🔴 紧急 | 系统异常 | 立即推送 |
| 🟡 重要 | Agent完成/记忆跟进 | 排队推送（用户空闲时） |
| 🟢 普通 | 定时提醒 | 低优排队 |
| 🔵 低优 | 日常问候 | 只在用户长时间空闲时推 |

### 4.4 消息生成方式

| 场景 | 生成方式 | 例子 |
|:----|:--------|:-----|
| 定时提醒 | 模板填充 | "主人，该喝水了~" |
| 系统告警 | 模板填充 | "磁盘占用90%，建议清理" |
| 话题跟进 | 调LLM | 从记忆取话题 → LLM生成关心的话 |
| Agent完成 | 调LLM润色 | 子Agent结果 → LLM润色成汇报 |

### 4.5 存储策略

```
主动引擎生成消息
       │
       ├─ 🔴 紧急/工具性 → tag="ephemeral" → 不存长期记忆
       ├─ 🟢 有意义交互 → tag="memorable" → 正常存长期记忆
       │
       用户回复后，回溯原始消息的tag：
         ephemeral → 用户回复也不存（如"好的"）
         memorable → 正常走 memory.add()
```

## 七、📁 子 Agent 数据生命周期

### 7.1 上下文与会话的生命周期

```
               子 Agent 的上下文
                      │
              ┌───────┴───────┐
              │               │
         工作空间级别       长期记忆级别
         ───────────       ───────────
         对话历史           情感分析结果
         工具调用记录       重要性评分
         当前进度           向量嵌入
         临时缓存           ChromaDB存储
              │               │
              │ 工作空间删除    │ 独立保留
              │ 就跟着消失      │ Agent配置不删就不丢
              ▼               ▼
            🗑️ 消失          💾 永久保留
```

**核心规则**：
- **工作空间删除 → 临时上下文消失**（对话历史、进度等）
- **Agent 配置不删 → 长期记忆就还在**（下次用同一个 Agent 还能想起来）
- **Agent 配置删除 → 长期记忆也跟着清理**（可选，可配置是否保留）

### 7.2 数据隔离示意

```
系统资源（全局复用）          工作空间（临时绑定）        长期记忆（Agent专属）
─────────────────          ──────────────────        ─────────────────
模型提供商池 ──────┐        workspace_001              ChromaDB:
人格预设池   ──────┼────→   ├─ agent: code            collection_code
知识库       ──────┘        │  ├─ 会话历史 ← 删        collection_design
                            │  ├─ 当前进度 ← 删        collection_test
Agent配置:                  │  └─ 任务列表 ← 删
├─ code (引用模型+人格+知识库)│
├─ design (引用模型+人格+知识库)│  workspace_002
└─ test  (引用模型+人格+知识库)│  ├─ agent: code
                              │  └─ ...（全新会话）
```

## 九、典型工作流示例

### 场景：主人说"做个博客网站"

```
① 用户: 做个博客网站
     → 自动路由到主脑（无 @）

② 主脑: 好的，我来拆解任务...
     → 调用 decompose_task("做个博客网站")
     → 返回: [{code, 前端}, {design, UI}, {backend, API}]
     → 创建工作空间 "博客项目"
     → 自动跳转工作空间页面

③ 主脑: @code 用Vue搭建前端框架
     → 路由到 code_agent 的会话
     → code_agent: 收到，开始搭建...
     → （code_agent 在自己的会话里工作，实时输出进度）

④ 主脑: @design 设计博客的UI风格
     → 路由到 design_agent 的会话
     → design_agent: 好的，我先设计几个方案...
     → （design_agent 同时工作，两个会话独立进行）

⑤ code_agent: @主脑 前端框架搭建完成，需要审核
     → 路由回主脑会话
     → 主脑: 让我看看代码...不错，结构清晰 👍

⑥ 主脑: 主人，code_agent 已经把前端搭好了
     → 用户: 好的，我看看

⑦ 用户: @design 颜色改成蓝色系
     → 路由到 design_agent 会话
     → design_agent: 好的，我调整一下配色方案...

⑧ 所有 Agent 完成后
     → 主脑汇总 → 向用户汇报最终结果
```

### 场景：电脑断电重启

```
① 服务器启动
     → 扫描 data/workspaces/
     → 发现 "博客项目" 状态为 active
     → code 已完成，design 做到一半

② 主脑主动推送（SSE）:
     "主人，刚才电脑重启了~
      博客项目进度：
      ✅ code_agent 已完成
      🔄 design_agent 做到一半（85%）
      要继续吗？"

③ 用户: 继续
     → 主脑重新派发 design_agent 的任务
     → design_agent 从上次的对话历史恢复上下文
     → 继续工作
```
