## 1. 概述与设计理念

### 1.1 项目定位

FeiyunMY-Bot 是一个轻量级 AI 聊天机器人管理平台。前端作为用户与后端系统之间的交互层，需要承载**对话交互**与**系统管理**两大核心场景。设计上追求**专业感**与**易用性**的平衡——让新手用户能快速上手对话，让高级用户能精细调校系统参数。

### 1.2 设计原则

- **暗红色主调**：区别于常见的深蓝/纯黑技术栈，暗红色赋予界面独特的品牌辨识度，传递"沉稳中蕴含能量"的视觉语言。
- **双层导航**：顶栏负责全局页面切换（仪表盘 / Chat），侧栏负责仪表盘内子模块切换，层级清晰不混淆。
- **渐进式复杂度**：常用功能（对话、会话切换）保持一目了然，高级功能（MCP、子代理编排）按需深入。
- **双主题支持**：暗红色模式适合长时间工作场景，浅色模式适合明亮环境或偏好清爽风格的用户，一键切换。

### 1.3 页面总览

本前端包含以下核心页面/视图：

| 页面 | 路径 | 说明 |
|------|------|------|
| 开场动画 | `/` | 启动时全屏展示 Logo 和项目名 |
| 仪表盘 | `/dashboard` | 系统管理主页，含侧栏 9 个标签 |
| Chat | `/chat` | AI 对话交互页面 |

> 注：仪表盘和 Chat 的切换通过顶栏按钮实现，不涉及路由跳转的页面刷新，保持 SPA 体验的流畅性。

## 2. 全局布局结构

### 2.1 顶栏（Top Bar）

顶栏是所有页面的共有组件，固定于视口顶部，不随页面滚动而隐藏。

#### 2.1.1 布局分区

```
┌──────────────────────────────────────────────────────────────┐
│  [Logo]  FeiyunMY-Bot         仪表盘 | Chat          [  ⋯  ] │
│  左侧                            右侧                      最右│
└──────────────────────────────────────────────────────────────┘
```

| 区域 | 位置 | 内容 | 说明 |
|------|------|------|------|
| **品牌区** | 左上角 | Logo 图标（小尺寸） + 项目名称 "FeiyunMY-Bot" | 点击可返回仪表盘首页 |
| **页面切换区** | 右上角 | 两个按钮：「仪表盘」「Chat」 | 当前所在页面按钮高亮，视觉上呈"激活态" |
| **菜单按钮** | 最右侧 | 省略号按钮（⋯） | 点击弹出下拉菜单，用于低频操作 |

#### 2.1.2 页面切换按钮

- 「仪表盘」和「Chat」为**互斥切换**，同一时刻只有一个处于激活状态。
- 激活态样式：底色加深（暗红色模式下为深红填充 + 亮红文字；浅色模式下为浅灰底 + 主题色文字）。
- 非激活态样式：透明底色 + 次级文字色，hover 时轻微变亮/变深。
- 切换时内容区域以**淡入淡出过渡**（约 200ms），不产生页面跳转感。

#### 2.1.3 省略号菜单（⋯ 按钮）

点击省略号按钮后，在其正下方弹出下拉菜单，菜单包含以下选项：

| 菜单项 | 图标示意 | 功能 |
|--------|----------|------|
| **浅色模式** | ☀️ / 太阳图标 | 将主题切换为浅色模式 |
| **暗红色模式** | 🌙 / 月亮图标 | 将主题切换为暗红色模式 |

交互细节：

- 当前激活的主题模式，其对应菜单项左侧显示勾选标记（✓）。
- 菜单以外区域点击（即"点击外部"）可关闭菜单。
- 菜单出现时带有轻微的下滑 + 淡入动画（约 150ms）。
- 主题切换触发时，整个页面颜色平滑过渡（CSS transition，约 300ms），避免突兀的颜色跳变。
- 主题偏好自动保存至浏览器本地存储（localStorage），下次访问时自动恢复。

## 3. 主题配色方案

### 3.1 暗红色模式（默认主题）

这是 FeiyunMY-Bot 的**标志性主题**。主色调选用暗红色系，区别于千篇一律的深蓝/纯黑技术面板，营造温暖但不失专业感的工作环境。

#### 3.1.1 色板总览

| 色彩角色 | 色值 | 用途 |
|----------|------|------|
| **主色（Primary）** | `#8B1A2B` | 关键按钮、激活态标识、链接文字、重点强调元素 |
| **主色悬停** | `#A01F33` | 按钮 hover 状态 |
| **主色浅层** | `#C9465C` | 次要高亮、通知徽章 |
| **背景-底层** | `#1A1012` | 页面最底层背景（接近黑色但带有红色底调） |
| **背景-卡片** | `#241518` | 卡片、面板、侧栏背景 |
| **背景-悬浮** | `#2D1A1E` | hover 状态下的卡片/列表项 |
| **背景-输入框** | `#1E1315` | 输入框、下拉菜单背景 |
| **边框-默认** | `#3A2228` | 卡片边框、分隔线 |
| **边框-高亮** | `#8B1A2B` | 聚焦态输入框边框、激活标签边框 |
| **文字-主要** | `#EDE0D4` | 正文、标题（暖白，非纯白以减少对比疲劳） |
| **文字-次要** | `#B8A0A0` | 辅助说明、placeholder、图标 |
| **文字-禁用** | `#6B5055` | 禁用态文字 |
| **成功色** | `#3D8B40` | 成功状态、在线标识 |
| **警告色** | `#C77D20` | 警告提示 |
| **错误色** | `#C9463A` | 错误状态、删除按钮 |
| **信息色** | `#5A7DA8` | 信息提示、链接 |

#### 3.1.2 色彩应用规则

- **大面积背景**使用"背景-底层"（`#1A1012`），让整个页面有一层"暗红底调"的氛围，而非纯黑。
- **卡片和面板**使用"背景-卡片"（`#241518`），与底层形成轻微分层，增强空间感。
- **侧栏**可考虑比卡片略深或略浅（如 `#1E1315`），从视觉上与内容区域区分。
- **顶栏**使用"背景-卡片"色或略深，下方加一条细微的边框分隔线。
- **主色 `#8B1A2B`** 使用克制——仅在需要引导注意力的地方出现（激活按钮、当前标签、通知红点），避免满屏红色造成视觉疲劳。
- **文字**不使用纯白（`#FFF`），改用暖白（`#EDE0D4`），在暗背景上阅读更舒适。

### 3.2 浅色模式

浅色模式是暗红色模式的对应主题，适用于明亮环境或偏好清爽界面的用户。配色上保留了红色的品牌基因，但大幅降低饱和度和深度，确保明亮干净。

#### 3.2.1 色板总览

| 色彩角色 | 色值 | 用途 |
|----------|------|------|
| **主色（Primary）** | `#8B1A2B` | 关键按钮、激活标识（与暗色模式保持一致以维护品牌色） |
| **主色悬停** | `#A01F33` | 按钮 hover |
| **主色浅层** | `#C9465C` | 次要高亮 |
| **背景-底层** | `#FBF8F7` | 页面最底层背景（暖白，略带红调） |
| **背景-卡片** | `#FFFFFF` | 卡片、面板、侧栏背景 |
| **背景-悬浮** | `#F5EEEC` | hover 状态下的卡片/列表项 |
| **背景-输入框** | `#FFFFFF` | 输入框背景 |
| **边框-默认** | `#E5D5D2` | 卡片边框、分隔线 |
| **边框-高亮** | `#8B1A2B` | 聚焦态边框 |
| **文字-主要** | `#2D181C` | 正文、标题 |
| **文字-次要** | `#7A6065` | 辅助说明、placeholder |
| **文字-禁用** | `#BFA8AC` | 禁用态文字 |
| **成功色** | `#2E7D32` | 成功状态 |
| **警告色** | `#B86E10` | 警告提示 |
| **错误色** | `#C62828` | 错误状态 |
| **信息色** | `#3D6A94` | 信息提示 |

#### 3.2.2 浅色模式设计要点

- **背景采用暖白而非冷白**（`#FBF8F7`），保持与品牌暗红色调的情感一致性。
- 卡片使用纯白（`#FFFFFF`），在暖白底层上形成清晰的层级。
- **主色保持不变**（`#8B1A2B`），这是品牌的视觉锚点，在两个主题中都是"FeiyunMY-Bot 的红色"。
- 文字色使用深棕色调而非纯黑，柔和且与红色品牌调性呼应。

### 3.3 主题切换过渡

- 在 `<html>` 或 `<body>` 标签上切换 CSS 类名（如 `theme-dark` ↔ `theme-light`）。
- 全局设置 `transition: background-color 0.3s ease, color 0.3s ease, border-color 0.3s ease`，确保颜色切换平滑。
- 图标（太阳/月亮）也可以做旋转动画增强趣味性。

## 4. 开场动画

### 4.1 触发时机

- 用户首次访问网站时触发（或每次打开新标签页时触发，根据产品策略决定）。
- 如果用户在开场动画期间刷新页面，动画重新播放。
- 后续可在设置中增加"跳过开场动画"选项（未来迭代）。

### 4.2 动画设计

#### 4.2.1 视觉布局

```
┌──────────────────────────────────────────┐
│                                          │
│                                          │
│             [Logo 图片]                  │
│          （居中，大尺寸）                 │
│            约 200×200px                  │
│                                          │
│          FeiyunMY-Bot                    │
│        （项目名称，大字）                  │
│                                          │
│         一行简短副标题（可选）             │
│        "轻量级 AI 聊天机器人"             │
│                                          │
│                                          │
└──────────────────────────────────────────┘
```

- 背景：暗红色主题色或渐变（从 `#1A1012` 到 `#241518` 的径向渐变）。
- Logo 图片：居中放置，路径为 `webui/assets/logo.png`（需将 `F:\FeiyunMY-Bot\logo.png` 复制到前端 UI 资源目录中）。
- 项目名称：Logo 下方，字号约 32-40px，字体加粗，颜色为暖白（`#EDE0D4`）。
- 可选副标题：名称下方约 16px 间距，字号 14-16px，颜色为次要文字色。

#### 4.2.2 动画时间线

| 阶段 | 时长 | 描述 |
|------|------|------|
| **阶段一：Logo 淡入** | 0 ~ 600ms | Logo 从透明度 0 渐显至 1，伴随轻微上浮（translateY 约 20px → 0） |
| **阶段二：名称浮现** | 400ms ~ 1000ms | 项目名称在 Logo 显现后开始淡入 + 上浮，与 Logo 动画有 200ms 重叠 |
| **阶段三：副标题出现** | 800ms ~ 1200ms | 副标题淡入（可选） |
| **阶段四：保持展示** | 1200ms ~ 2800ms | 全部元素稳定显示约 1.6 秒，期间可以有微弱的呼吸光效（Logo 外围光晕缓慢变化） |
| **阶段五：过渡至主界面** | 2800ms ~ 3400ms | 整体画面淡出（opacity → 0），同时主界面从背后淡入，约 600ms 交叉过渡 |

总时长约 **3 ~ 3.5 秒**。用户也可以点击动画画面任意位置**跳过动画**，立即进入主界面。

#### 4.2.3 进入主界面

- 动画结束后自动跳转到默认页面（建议为**仪表盘首页**，即 `/dashboard`）。
- 如果用户之前有未关闭的对话会话，也可以考虑跳转到 Chat 页面（未来迭代功能）。
- 跳转过程中保持顶栏和侧栏的渲染，让过渡自然。

### 4.3 资源准备

- 将 `F:\FeiyunMY-Bot\logo.png` 复制到前端项目的 `webui/assets/logo.png`（或 `public/assets/logo.png`，视框架约定）。
- 建议同时准备一个 SVG 版本的 Logo（如果可能），以便在高分辨率屏幕上保持清晰。

## 5. 仪表盘页面

### 5.1 页面布局

```
┌─────────────────────────────────────────────────────────────┐
│                      顶栏 (Top Bar)                         │
├────────────┬────────────────────────────────────────────────┤
│            │                                                │
│  侧栏      │           内容区域                             │
│  (Sidebar) │           (Content)                            │
│            │                                                │
│  9个标签   │   当前选中标签对应的功能面板                    │
│  垂直排列  │                                                │
│            │                                                │
│            │                                                │
│            │                                                │
└────────────┴────────────────────────────────────────────────┘
```

- **侧栏**：固定宽度约 200-220px，左侧排列，高度撑满顶栏以下区域。
- **内容区域**：占据剩余宽度，内边距约 24-32px，可滚动。
- 侧栏与内容区域之间有一条分隔线（边框色）。

### 5.2 侧栏设计

#### 5.2.1 标签列表

按从上到下的顺序排列，共 9 个标签：

| 序号 | 标签名 | 图标建议 | 功能简述 |
|------|--------|----------|----------|
| 1 | **首页** | 🏠 Home | 系统概览，关键指标一览 |
| 2 | **人格** | 🎭 Persona | 管理 AI 人格预设 |
| 3 | **配置** | ⚙️ Settings | 全局配置项管理 |
| 4 | **Skills** | 🧩 Puzzle | 技能包管理 |
| 5 | **MCP** | 🔌 Plug | MCP 服务器管理 |
| 6 | **对话数据** | 💬 Message | 历史对话记录查看与管理 |
| 7 | **子代理编排** | 🔗 Branch | 子代理系统配置与监控 |
| 8 | **数据统计** | 📊 Chart | 使用统计与可视化 |
| 9 | **平台日志** | 📋 Log | 系统运行日志查看 |

#### 5.2.2 侧栏交互

- 当前选中的标签呈**激活态**：背景色为主色（暗红模式下）或浅红色底（浅色模式下），文字变为白色或主色，左侧可加一条 3px 宽的竖线作为选中指示器。
- 未选中的标签：透明背景，次要文字色，hover 时背景轻微变亮/变深。
- 标签之间间距约 2-4px，形成一个紧凑但不拥挤的列表。
- 侧栏顶部（标签列表上方）可加一个小的分组标题如"导航"或直接留白。
- 侧栏底部可预留：版本号、API 连接状态指示灯。

### 5.3 各标签页内容描述

#### 5.3.1 首页（概览）

首页是仪表盘的默认入口，提供一个**系统健康状态的鸟瞰视图**。

**功能区块**：

| 区块 | 内容 | 数据来源 |
|------|------|----------|
| **系统状态卡片** | 服务运行状态（运行中/已停止）、运行时长（uptime）、API 连接状态 | `GET /api/system/stats`、`POST /api/provider/test` |
| **资源监控卡片** | CPU 使用率、内存使用率、磁盘使用率（进度条 + 数值） | `GET /api/system/stats` |
| **当前配置摘要** | 当前激活的人格名称、记忆模式、使用的模型名称 | `GET /api/config`、`GET /api/personas` |
| **最近对话** | 最新的 3-5 条会话摘要（标题 + 最后活跃时间），点击可跳转至 Chat 页面 | `GET /api/sessions` |
| **快捷操作** | 几个常用操作的快捷按钮：切换人格、测试 API 连接、打开 Chat | —— |

**布局建议**：卡片式网格布局，大屏幕 3 列，中等屏幕 2 列，小屏幕 1 列。

---

#### 5.3.2 人格（Persona）

管理 AI 的性格和行为方式。

**功能区块**：

| 区块 | 内容 |
|------|------|
| **人格列表** | 以卡片或表格展示所有已安装的人格（预设 + 自定义），每项显示名称、描述、是否激活 |
| **激活切换** | 点击某个人格的"激活"按钮，将其设为当前使用的人格，后端热切换，无需重启 |
| **新建人格** | 弹窗表单：填写名称、描述、系统提示词（System Prompt）、预设对话示例 |
| **编辑人格** | 修改现有人格的配置 |
| **删除人格** | 删除自定义人格（预设人格不可删除或需确认） |
| **人格预览** | 可选：展示人格的 System Prompt 摘要和预设对话片段 |

**交互细节**：
- 当前激活的人格卡片有醒目的激活标识（如绿色边框或"使用中"标签）。
- 切换人格时弹出一个确认提示："切换人格将影响后续所有对话的回复风格，确认切换？"
- 新建/编辑人格使用模态框（Modal），内有 System Prompt 的文本编辑器（建议支持多行输入和简单高亮）。

**相关 API**：人格 CRUD 接口（`GET/POST/PUT/DELETE /api/personas/*`）。

#### 5.3.3 配置（Config）

全局系统配置管理中心。

**功能区块**：

| 区块 | 内容 |
|------|------|
| **Provider 配置** | API 地址、API Key（脱敏显示）、模型选择（下拉列表，通过测试连接获取可用模型）、Temperature、Max Tokens、Top-P 等参数 |
| **工具开关** | 以开关列表展示所有工具的启用/禁用状态（web_search、file_ops、code_exec 等），每个开关附工具说明 |
| **搜索配置** | 搜索引擎选择（Baidu / DuckDuckGo / SerpAPI 等）、对应 API Key 配置 |
| **记忆配置** | 记忆模式切换（Simple / Memoria）、相关参数 |
| **Shell 白名单** | 允许执行的命令列表，支持增删，每项有命令名和说明 |

**交互细节**：
- 每个配置项都有明确的标签和说明文字。
- API Key 类字段使用密码输入框样式，默认脱敏显示（如 `sk-****xxxx`），旁边有"显示/隐藏"切换按钮。
- 修改配置后，点击"保存"按钮提交，成功后弹出 toast 提示"配置已保存"。
- 危险配置项（如修改 API 地址）保存时给出二次确认。

**相关 API**：配置读写接口（`GET/POST /api/config`）、工具开关（`POST /api/tools/toggle`）、搜索引擎管理、Shell 白名单管理等。

#### 5.3.4 Skills（技能）

管理 AI 的技能包——可安装的扩展能力模块。

**功能区块**：

| 区块 | 内容 |
|------|------|
| **已安装技能列表** | 表格展示已安装技能：名称、版本、描述、安装时间、状态（启用/禁用） |
| **安装新技能** | 两种方式：(1) 从 Skills 市场搜索并安装 (2) 拖拽 zip 包到指定区域上传安装 |
| **技能详情** | 点击某个技能展开其详细信息，包括 SKILL.md 内容预览 |
| **启用/禁用** | 每个技能有独立开关 |
| **卸载技能** | 删除已安装技能（二次确认） |

**交互细节**：
- "安装技能"区域设计一个明显的拖拽区（dashed border），提示"拖拽 .zip 技能包到此处，或点击选择文件"。
- 安装过程展示进度（上传 → 解压 → 安装 → 完成）。
- 如果技能有依赖或版本冲突，给出明确提示。

**相关 API**：Skills CRUD 接口（`GET/POST/PUT/DELETE /api/skills/*`）。

#### 5.3.5 MCP（Model Context Protocol）

管理 MCP 服务器——让 AI 能调用外部工具和数据源。

**功能区块**：

| 区块 | 内容 |
|------|------|
| **MCP 服务器列表** | 表格展示已配置的 MCP 服务器：名称、地址/命令、状态（连接中/在线/离线）、启停开关 |
| **添加服务器** | 表单：填写服务器名称、类型（stdio / SSE / streamable HTTP）、连接参数（命令或 URL） |
| **编辑服务器** | 修改已有配置 |
| **删除服务器** | 移除配置（二次确认） |
| **连接测试** | 每个服务器旁边有"测试连接"按钮，点击后显示连接结果 |
| **状态指示** | 在线/离线用绿色/灰色圆点标识 |

**交互细节**：
- 服务器列表支持展开查看详细配置。
- 状态检测可设为定时轮询（如每 30 秒）或手动刷新。
- 添加服务器时，提供不同连接类型的表单切换（stdio 显示命令输入框，HTTP 显示 URL 输入框）。

**相关 API**：MCP 服务器管理接口（`GET/POST/PUT/DELETE /api/mcp/servers/*`）。

#### 5.3.6 对话数据（Conversation Data）

查看和管理历史对话记录。

**功能区块**：

| 区块 | 内容 |
|------|------|
| **会话列表** | 以时间倒序展示所有会话，每条显示：标题、消息数、创建时间、最后活跃时间 |
| **搜索与筛选** | 按关键词搜索对话内容，按时间范围筛选，按会话标题筛选 |
| **对话详情查看** | 点击某个会话，展开其完整对话记录（类似聊天界面的只读模式） |
| **导出对话** | 将选中会话导出为 JSON / Markdown / 纯文本格式 |
| **删除会话** | 删除单个会话或批量删除（二次确认） |

**交互细节**：
- 对话详情以聊天气泡形式展示，用户消息和 AI 回复用不同颜色区分，但整体为只读模式。
- 搜索功能支持全文搜索，搜索结果高亮显示匹配关键词。
- 导出格式选择：下拉菜单选择 JSON（完整数据）/ Markdown（可读性好）/ TXT（纯文本）。

**相关 API**：会话管理接口（`GET/POST/PUT/DELETE /api/sessions/*`）、对话日志查询。

**交互细节**：

- 活跃的分对话以实时面板展示，显示子代理当前的思考/工具调用状态。

### 6.2 左侧面板：会话管理

#### 6.2.1 面板结构

从上到下依次为：

| 区块 | 说明 |
|------|------|
| **搜索栏** | 输入框，支持按会话标题模糊搜索 |
| **新建会话按钮** | 醒目的按钮，点击创建空白新会话 |
| **会话列表** | 所有会话按最后活跃时间倒序排列 |

#### 6.2.2 会话列表项

每个会话列表项显示：

- **会话标题**：自动生成或用户手动设置的标题
- **最后一条消息摘要**：显示最后一条消息的前几个字（截断约 25 个字符）
- **时间戳**："刚刚" / "5分钟前" / "2小时前" / "昨天" / 具体日期
- **消息数量**：小徽章显示该会话的消息总数

#### 6.2.3 会话操作

| 操作 | 触发方式 | 说明 |
|------|----------|------|
| **切换会话** | 单击列表项 | 右侧聊天区域切换到该会话的完整历史 |

| **删除会话** | 右键菜单/悬停出现删除图标 | 二次确认后删除 |
| **自动命名** | 按钮/菜单 | 调用后端接口，由 AI 根据对话内容自动生成标题 |

#### 6.2.4 交互细节

- 当前活跃的会话列表项呈**激活态**（背景色高亮，左侧有指示条）。
- 新建会话后，自动切换到新会话并聚焦输入框。
- 会话列表支持滚动，如果会话数量多，保持搜索栏和新建按钮固定（不随列表滚动）。
- 左侧面板宽度约 260-300px，可通过拖拽分隔线调整宽度（可选功能）。

### 6.3 右侧区域：聊天主页面

#### 6.3.1 消息展示

聊天区域是 Chat 页面的核心，展示当前会话的完整消息历史。

**消息类型与样式**：

| 消息类型 | 对齐方式 | 气泡样式 | 额外内容 |
|----------|----------|----------|----------|
| **用户消息** | 右对齐 | 主色背景（暗红），白色/暖白文字，右下角圆角缩小 | 时间戳（小字，气泡下方） |
| **AI 回复** | 左对齐 | 卡片背景色，暖白/深色文字，左下角圆角缩小 | 时间戳 + 思考过程（如有） |
| **系统消息** | 居中 | 浅色/灰色背景，小字，无气泡 | 如"会话已创建"、"工具调用开始" |
| **工具调用** | 左对齐（嵌套在 AI 回复中） | 特殊样式：左侧边框 + 图标 + 工具名 + 参数摘要 | 可折叠展开查看详情 |
| **错误消息** | 居中/左对齐 | 错误色背景，浅色文字 | 错误描述 + 重试按钮（如适用） |

**AI 思考过程展示**：

- 如果 AI 在回复前有思考过程（如 DeepSeek 的 `reasoning_content`），在 AI 回复气泡上方展示一个可折叠的"思考中…"区域。
- 折叠状态：显示为一行灰色小字 "🤔 思考过程 (点击展开)"。
- 展开状态：显示完整的思考文本，使用次级文字色和稍小的字号，与正式回复形成视觉区分。

**流式输出**：

- AI 回复支持流式渲染（SSE），文字逐字出现，光标闪烁效果（类似打字机）。
- 流式输出期间，消息气泡底部显示一个跳动的光标（`|` 字符闪烁动画）。
- 流式输出完毕后，光标消失，消息定型。

#### 6.3.2 输入区域

位于聊天区域底部，固定在视口下方。

| 元素 | 说明 |
|------|------|
| **消息输入框** | 多行文本输入框（textarea），自动调整高度（最小2行，最大6行），支持 Enter 发送（Shift+Enter 换行） |
| **发送按钮** | 位于输入框右侧，主色背景 + 发送图标（➤），AI 正在回复时变为"停止生成"按钮 |
| **附加功能（可选）** | 输入框上方或左侧可放置几个小按钮：清空上下文、切换流式/非流式模式 |

**交互细节**：

- 输入框在 AI 回复期间不锁定（用户可以提前输入下一条消息），但发送按钮变为"停止生成"。
- 空消息不可发送，发送按钮在输入框为空时呈禁用态。
- 正在流式输出时点击"停止生成"，中断 SSE 连接，保留已输出的部分内容。

#### 6.3.3 会话标题栏

在聊天区域顶部，显示当前会话的标题（可编辑）和一些操作按钮：

| 元素 | 说明 |
|------|------|
| 会话标题 | 大字显示，可点击编辑或通过右侧面板重命名 |
| 自动命名按钮 | 魔法棒图标，点击触发 AI 自动生成标题 |
| 清空上下文 | 清除当前会话的消息（保留会话本身） |
| 导出对话 | 导出当前会话的完整内容 |

### 6.4 空状态

当没有选中任何会话时，聊天主区域展示空状态引导：

- 居中显示一个大的图标或插图（聊天气泡图标）。
- 文字："选择一个会话开始对话" 或 "点击左侧 '+ 新建' 创建新会话"。
- 也可以在此展示一个快捷引导：一个显眼的"开始新对话"按钮。

## 7. 响应式与可访问性

### 7.1 响应式设计

| 屏幕宽度 | 布局调整 |
|----------|----------|
| **≥ 1024px**（桌面） | 完整布局：顶栏 + 侧栏/会话面板 + 内容区域，所有功能可见 |
| **768px ~ 1023px**（平板） | 侧栏/会话面板可折叠（汉堡菜单触发），内容区域占满宽度 |
| **< 768px**（手机） | 单列布局：顶栏收缩为仅 Logo + 汉堡菜单 + ⋯ 按钮；侧栏/会话面板变为抽屉式（从左侧滑出）；内容区域占满屏幕 |

### 7.2 可访问性要点

- 所有交互元素（按钮、链接、输入框）支持键盘导航（Tab 键切换，Enter/Space 激活）。
- 主题切换考虑 `prefers-color-scheme` 媒体查询，首次访问时可跟随系统主题偏好。
- 图标按钮提供 `aria-label` 描述。
- 颜色对比度满足 WCAG AA 标准（主要文字与背景对比度 ≥ 4.5:1）。

### 8.3 状态管理

| **当前页面** | 组件内部 state 或 URL 路由 | "仪表盘" vs "Chat" |
| **仪表盘当前标签** | 组件内部 state | 9个标签中哪个被选中 |
| **会话列表** | 全局状态管理 | Chat 页面和对话数据页面共享 |
| **当前会话消息** | 局部状态（Chat 页面内） | 当前活跃会话的消息历史 |
| **配置数据** | 按需获取 + 缓存 | 各面板独立管理自己的配置数据 |

## 9. 交互流程与状态管理

### 9.1 主题切换流程

```
用户点击 ⋯ 按钮
  → 下拉菜单弹出（下滑 + 淡入，150ms）
  → 用户点击「浅色模式」/「暗红色模式」
  → 菜单关闭
  → 页面颜色平滑过渡（300ms）
     - 背景色、文字色、边框色、卡片色全部过渡
  → 主题偏好写入 localStorage
  → 菜单项勾选标记更新
```

### 9.2 仪表盘导航流程

```
用户点击侧栏标签
  → 当前标签取消激活态
  → 新标签变为激活态（左侧指示条滑动或瞬间切换）
  → 内容区域淡入切换到对应面板（200ms）
  → 面板内容按需从后端 API 获取数据
  → 加载中显示 LoadingSpinner
  → 数据到达后渲染内容
```

### 9.3 Chat 对话流程

```
用户选择会话（或新建会话）
  → 右侧聊天区域加载该会话的历史消息
  → 消息列表滚动至底部
  → 输入框自动聚焦

用户输入消息并发送
  → 用户消息气泡立即出现在消息列表中
  → 输入框清空
  → 消息列表滚动至底部
  → 发送按钮变为「停止生成」按钮
  → SSE 连接建立
  → AI 回复气泡出现，内容逐字流式输出
     - 如有思考过程，先展示可折叠的思考块
     - 如有工具调用，展示工具调用消息
  → 流式输出完毕
  → 「停止生成」按钮恢复为发送按钮
  → 消息列表再次滚动至底部
```

### 9.4 全局 API 状态处理

| 状态 | 处理方式 |
|------|----------|
| **加载中** | 各面板/组件显示骨架屏或加载动画 |
| **加载成功** | 数据正常渲染 |
| **加载失败** | 显示错误提示 + 重试按钮，toast 通知 |
| **API 不可达** | 顶栏状态指示灯变红，全局提示"无法连接到服务器" |
| **限流触发（429）** | toast 提示"请求过于频繁，请稍后再试"，禁用发送按钮若干秒 |
